# Reuse audit: what to depend on, adapt, or leave upstream

Prefer a released dependency or pinned executable to copying a repository. A fork is justified only if the existing interface cannot meet a demonstrated requirement and the team agrees to maintain the fork. Repository license labels below come from GitHub metadata or the project itself; review the exact pinned release and transitive dependencies before distribution.

| Candidate | Reuse decision | Fit and limits |
| --- | --- | --- |
| [similar](https://github.com/mitsuhiko/similar), Apache-2.0 | **Use the crate now.** | Generates unified diffs with file headers, context, and missing-newline markers. Replaces the hand-written formatter. It receives only two file versions generated in the trusted verifier; it does not consume or apply guest diff text. |
| [pulldown-cmark](https://github.com/pulldown-cmark/pulldown-cmark), [clap](https://github.com/clap-rs/clap), [Serde](https://github.com/serde-rs/serde), and [RustCrypto hashes](https://github.com/RustCrypto/hashes) | **Use crates, not copied code.** | Reuse Markdown structure and source ranges, CLI parsing, JSON serialization, and SHA-256. A Markdown event span does not tell us exactly which destination bytes we may replace, so retain a narrow, tested selector and edit rule. |
| [Lychee](https://github.com/lycheeverse/lychee), Apache-2.0 | **Evaluate the upstream CLI for a future broader link-check job.** | Already discovers and checks links, including local links. It does not bind an occurrence to the dispatch-approved change, constrain the bytes edited, or emit factory evidence. Pulling its broader network-oriented checker into the first offline job would not replace those rules. |
| [diffy](https://crates.io/crates/diffy), MIT or Apache-2.0 at the checked release | **Alternative, not a parallel dependency.** | Offers patch creation and application. This job only needs review diff generation; retain one formatter dependency rather than adding a patch-applier. |
| [Codex](https://github.com/openai/codex), Apache-2.0 | **Reuse a pinned release as a later agent adapter if selected. Do not fork.** | Rust model/tool runtime and scriptable interfaces already exist. The deterministic pilot needs none of the agent runtime, approvals or session machinery. Keep our verification independent. |
| [Sandcastle](https://github.com/mattpocock/sandcastle), MIT | **Reference or bounded adapter evaluation, not a default runner.** | Its documented branch strategies can write back to host checkouts, and Docker bind-mount providers expose worktree/Git state. Reuse only if an isolated provider demonstrably fits the patch-only handoff and credential policy. |
| [Symphony](https://github.com/openai/symphony), Apache-2.0; [SWE-bench](https://github.com/SWE-bench/SWE-bench), MIT | **Reuse design patterns, not full repos.** | Symphony is a long-lived issue orchestrator and does not provide our required trust policy. SWE-bench's Python/Docker evaluation separates generation and grading, but its runner and datasets solve a different problem than the small local CLI. |

The factory-specific code is the approved-intent contract, one-link scope, staged snapshot checks, verdict, and evidence binding. Before adding an integration, test one allowed and one denied case with the upstream tool first. Add an adapter only where the existing interface is a fit. No third-party source was copied or vendored.
